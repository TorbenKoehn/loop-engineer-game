# T099: Content string registry without hub-file edits

## Goal

Every content task so far added one import + one spread to `src/content/strings/en.ts` (and the bundle in `src/content/index.ts`), causing a merge conflict on every parallel content task (RT002 P1). Introduce a registry so a new content area is added by creating its own files only, e.g. a static list module that is generated by a small tool script (`npm run content:index`) and checked in CI, or a convention-based list that a test verifies is complete. No runtime glob (must run natively on Node 24, ADR-006).

- [ ] All existing keys and the content bundle are unchanged (existing tests pass; a test asserts key count equality before/after)
- [ ] The procedure is documented in docs/architecture/content-model.md
