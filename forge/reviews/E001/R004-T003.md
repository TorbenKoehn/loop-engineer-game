# R004: Review of T003

## Summary

Round 2. R003 F1 (major) is resolved. The cyrb128 finalisation is now sequential, as in
the reference, and the goldens are pinned to independent reference values. R003 F2
(minor) is addressed: `int`, `pick`, `weighted` and `shuffle` are exported, and the state
is `[a, b, c, d]`. AC3 follows sim-core.md as `fork(seed, path)`. Its intent
(deterministic, independent sub-streams) is met, and it is stronger than forking by
state.
- [x] AC1 verified: `npx vitest run src/sim/rng.test.ts` (20 passed). I re-ran the bryc
  cyrb128 + sfc32 reference in Node. It gives the same K7Q2-M9XA, fork, empty-seed,
  [1,2,3,4] and nextInt(100) values as the test.
- [x] AC2 verified: the test "serializes to JSON [a, b, c, d] and continues the
  sequence". `restore` rejects malformed state.
- [x] AC3 verified: fork determinism, independent of parent draws, plus the fast-check
  property "drawing from one fork does not alter another". The signature is
  `fork(seed, path)` per sim-core.md#rng, and the conflict is documented in the task
  Notes.
- [x] AC4 verified: the fast-check property for n in [1, 2^32]. nextInt uses integer
  rejection sampling on uint32 only.
- [x] AC5 verified: the test "rng purity" scans the source, and a manual read of
  rng.ts finds no Math.random, Date, timers, crypto or DOM.
- Checks: `npm run check` exit 0 (tsc 0, vitest pass, harness:check 0). The harness
  dir_subdirs warning comes from the planner's untracked E007+ epics. The only unstaged
  and untracked files are the planner's concurrent forge/ edits, which are out of scope.
