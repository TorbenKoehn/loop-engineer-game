# R055: Review of T050

## Summary

Round 1. This task adds `src/save/` with three modules:
- `checksum.ts`: canonical JSON and a synchronous SHA-256.
- `schema.ts`: `RunSaveV1` and `MetaSaveV1`, sealing and parsing.
- `storage.ts`: a `SaveStorage` adapter with memory fallback, key rotation and `saveRunEnd`.

The raw diff is 627+/21- lines. Production is 300 lines (checksum 72, schema 88, storage 140), under the 400 budget. Everything is staged and nothing is untracked. `npm run check` passed all steps, and harness lint reports 0 errors.

Judgement calls:
- **save.md corrections** (all accepted):
  - `setup: SetupSnapshot` matches `RunState.setup` in `src/run/state.ts:199`. `RunSetup` lacks the meta snapshot, so the old doc was wrong.
  - `SaveStorage` avoids shadowing the DOM `Storage` type.
  - Removing `le:run:backup` at run end stops a finished run from being restored from the backup.
  - ADR-005 is unchanged and still consistent. Its save fields match, and `gameVersion` is additive, as save.md already listed it.
- **Hand-written SHA-256:**
  - Padding is correct. The block count `((len+8)>>6)+1` is right at 55, 56 and 63 bytes, and the high length word is `len / 2^29`.
  - Arithmetic is kept in int32 with `|0` and `>>>0`. DataView reads big-endian.
  - I checked it beyond the shipped tests. It matches the FIPS 448-bit vector and the one-million-`a` vector (`cdc76e5c…`). It also matches 2000 random byte and emoji strings against node:crypto, with 0 mismatches.
  - The risk is acceptable. The checksum only detects corruption and tampering, the reason (pagehide) is documented, and the tests pin it to node:crypto.
- **Fallback semantics:**
  - A probe write at construction catches private mode and a missing `localStorage`.
  - A later throw switches to memory for good and copies the readable save keys, so in-session state stays coherent.
- **Readability:** cutting comments did not hurt. Every exported function and helper has a one-line doc comment, and the file headers link save.md. The 300-line count is well under the 400 error limit, so it was not a forced squeeze.

- [x] AC1 verified: `npx vitest run src/save` (3 files, 19 passed). schema.test.ts checks `text === canonicalJson(JSON.parse(text))`, the absence of whitespace, and `checksum === sha256Hex(canonicalJson(body))`. A tampered checksum and tampered data both return `error: 'checksum'`.
- [x] AC2 verified: storage.test.ts covers a throwing `open()`, a FakeWeb that throws on every call, and a FakeWeb whose later writes throw. In each case `memoryOnly` is true and reads and writes work from memory.
- [x] AC3 verified: `SAVE_KEYS` equals the four documented keys. The rotation test shows the second write moves A to `le:run:backup` (and meta 1 to `le:meta:backup`).
- [x] AC4 verified: the recorded FakeWeb call order is get meta, set meta:backup, set meta, remove run, remove run:backup. A crashing meta write leaves the run save intact.
