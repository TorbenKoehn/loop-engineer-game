# R038: Review of T041

## Summary

Round 1. Replaces the stub map with the seeded generator in `src/run/map/` (paths, node types, encounters, graph, generate). `MapNode` now has `type` and `encounter`, and `newRun` calls `generateMap(seed, 1, tutorial)`. The raw diff is 448+/45- lines including the task file and BOARD. Production is about 295 lines (new files 248, plus the state, apply and new-run changes and the 28-line map-stub deletion), under task_diff_lines 400. `npx vitest run src/run` gave 26 passed, `tsc --noEmit` and `biome check src/run` are clean, and `npm run check` passed with no src/run warnings. All changes are staged.

The generation rules match run-map.md: 7x5 grid, 4 paths, the first two starting in different columns, uniform clamped steps, the crossing test `a<c && b>d` or the reverse with 10 retries and then straight, deduplicated edges, every row-7 node linked to the boss, fixed rows 1/4/7, the weighted table with its exact weights and rows, 20 re-rolls then Task, and the adjacency rule for Critical Bug, Registry and Idle Cycle. They also match vertical-slice.md: 7 rows plus the boss and all 7 node types. Determinism holds. `fork(seed, 'map/<phase>')` drives paths and types in a fixed order. `fork(seed, 'encounter/<nodeId>')` drives each encounter, so it does not depend on generation order. Both match run-state.md#rng-fork-paths, node ids are `p<phase>-r<row>-c<col>` and `p<phase>-boss`, and no ambient randomness is used.

The GDD-gap choices in the Notes are reasonable. Ancestor-based exclusion is the right reading of "fought this phase" for encounters chosen at generation, because a player only walks one path. The tutorial column 2 and the Task-then-Standup conversion are fine: conversion cannot create a same-type edge because no node of that type exists yet.
