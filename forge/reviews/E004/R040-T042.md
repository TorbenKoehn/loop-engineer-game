# R040: Review of T042

## Summary

Round 1. Adds `src/run/combat.ts`, which builds `CombatInput` from run state and content and resolves it with `{log: false}`. It also adds the `continue` action, the `nextFight` and `combat` fields on RunState, and an orchestrator-authorised UI integration fix (a label for `continue` in `placeholder.tsx` and the `ui.action.continue` string). The raw diff is 312+/22- lines. Production is about 147 lines (combat.ts 96, state/apply/actions/new-run 48, UI 2), under task_diff_lines 400. `npx vitest run src/run src/ui` gave 58 passed, `tsc --noEmit` is clean, and `npm run check` passed with no src/run warnings. All changes are staged.

The builder matches the docs. In run-state.md, the seed is `forkSeed(setup.seed, 'combat/<nodeId>')` and the RunState fields `nextFight` and `combat {nodeId, input, outcome}` match the shape. `combatReview` allows only `continue`, and travel resolves without a log. In sim-core.md, the agent, skills, memories, lessons, prompt, policy, encounter and modifiers are all filled. `spawnDefs` is the transitive closure of the spawn verbs (opening, cycle, stage cycles) and the split children (traits, stage traits), excluding the starting line. `deadlineMs` comes from the encounter, with a fallback by pool. Applying the result clamps Trust at 0 and copies `maxTrust` and `usedOncePerRun`. The doc's "stats" part is explicitly deferred to E008 in the Notes. Determinism holds: there is no ambient randomness, and the fight is a pure function of state and content.
