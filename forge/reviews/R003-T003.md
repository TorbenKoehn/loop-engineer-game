# R003: Review of T003

## Summary

Round 1. The sfc32 core, nextInt rejection sampling, fork-by-path, serialize/restore and
tests are clean and deterministic, but the seed hash is not cyrb128 as
`docs/architecture/sim-core.md#rng` specifies, and the self-generated golden values lock
in the wrong hash.
- [x] AC1 verified: npx vitest run src/sim/rng.test.ts (11 passed). The goldens are
  stable, but they were generated by this implementation and do not match reference
  cyrb128+sfc32 (see F1)
- [x] AC2 verified: "serializes to JSON and continues the sequence" test; restore validates shape
- [x] AC3 verified: fork test + fast-check property; fork hashes `seed + '/' + label` per sim-core.md
- [x] AC4 verified: fast-check property for n in [1, 2^32]; integer-only modulo with rejection of the biased tail
- [x] AC5 verified: grep for Math.random|Date|performance|crypto|document|window|setTimeout in src/sim/rng.ts finds nothing
- Checks: npx tsc --noEmit = 0; fast-check is in committed package.json and the lockfile change is staged; git status shows no unstaged task files

Independent reference: bryc's reference cyrb128 + sfc32 (12 warm-up draws), run with Node.
- The sfc32 core matches the reference for 1000 draws from state [1,2,3,4].
- cyrb128('K7Q2-M9XA') should give [3484269380, 2477151036, 3197052215, 1924526633].
- The first 5 nextU32 for 'K7Q2-M9XA' should be [1816276898, 3579975248, 3831263920, 2491312191, 3589079935].
- The first 3 for the fork 'K7Q2-M9XA/combat/p1-r3-c2' should be [4244083357, 2713881700, 242476162].
- The test currently expects [2540926937, 1889446044, ...] and [2341509095, ...].

## Findings

| # | Sev | Where | Finding | Required fix |
|---|---|---|---|---|
| F1 | major | src/sim/rng.ts:29 | The cyrb128 finalisation differs from the reference. The reference updates in sequence (`h1 ^= h2^h3^h4; h2 ^= h1; h3 ^= h1; h4 ^= h1`, all using the new h1). Here h2..h4 are XORed with the old h1. This breaks the spec ("hashed with cyrb128"). It also makes the output singular: s[0] == s[1]^s[2]^s[3] for every seed (checked on 6 of 6 seeds), so the seed space drops to 96 bits. Once the goldens and shared or daily seeds are committed, the error is locked in. | Match the reference cyrb128 finalisation. Then regenerate the goldens and pin at least one sequence to the independent reference values above, so the test proves the algorithm and not just stability |
| F2 | minor | src/sim/rng.ts:68 | The API differs from sim-core.md#rng, which lists `int(rng, lo, hi)`, `weighted` and `shuffle` and serialises as `[a, b, c, d]`. The code has `range`, adds `nextU32` and `nextInt`, and serialises as `{seed, s}`. The task scope (nextInt, range, pick) is respected. | Align the doc and code naming (update sim-core.md or rename), and track weighted/shuffle in a later task |
