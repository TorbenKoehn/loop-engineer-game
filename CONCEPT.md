# Loop Engineer - Das Spiel

## Kurzform

Das Spiel handelt von Agents, die sich in einer Engineering Schleife befinden.

Es soll ein Rogue Lite Spiel sein.

Der Spieler spielt einen Agent. Das Spiel spielt sich mit Auto-Battle Mechanik

Man wählt am Anfang einen Harness (Bestimmen Skills, APIs etc.), mit dem
bestreitet man die Loop

Es gibt eine Kontext-Mechanik, die balanciert werden muss (z.B. wie Mana)

Gegner sind z.B. Kontext-Drift, nicht erreichbare Dienste, Sandbox-Dinge

## Dein eigener Harness

Du arbeitest mit Loop Engineering.

- Kontext verwaltest du in Markdown-Files mit Frontmatter
  - Frontmatter enthält title, summary, keywords und weitere sinnvolle referenzen
  - Files werden auf jeder Ebene in einer INDEX.md indiziert, denen Agents folgen können (mechanisch generiert)
  - Du baust dir eine Forge im Repo: Kanban Board, Epics, Tasks + Sub-Tasks, Reviews. Verwendet ebenfalls Frontmatter-Markdown mit Indexing.
- Du orchestrierst nur. Nutze Opus 5.5 oder Sonnet 5.5 je nach Aufgabe und delegiere deine Arbeit
- Du legst dir eigenständig Agent Skills an und wartest diese, um deine Effektivität zu optimieren. Auch Harness-Kontext-Dateien pflegst du eigenständig und regelmässig.
- Recherchiere alle notwendigen Best Practices dazu und erstelle einen passenden Harness.
- Alles kriegt ein Budget. Maximale Länge von MD-Files, maximale Anzahl von Doku-Dateien in einem Ordner vor Umordnung, maximale Anzahl von Tasks und Sub-Tasks pro Aufgabe, maximale Anzahl von Code-Kommentar-Längen etc. Finde alle sinnvollen Punkte zur Budgetierung.



Stelle mir alle notwendigen Fragen, um dein Verständnis meiner Vision zu optimieren
